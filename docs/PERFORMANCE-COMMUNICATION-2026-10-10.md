# 短信与电话：连接复用、请求预算、取消与真实结果

日期：2026-10-10。基线：后端 `301651b`；开发分支：`codex/communication-delivery-budgets`。

## 本批已完成

| 问题 | 改动 | 可验证收益 |
|---|---|---|
| SMS/Phone 适配器丢弃上游 context | Send/Test 都传递原始 context，保留可识别的取消错误 | 消费者停止/页面测试请求取消能够传到服务商请求；不会继续尝试后续号码 |
| 阿里云每个号码创建 SDK 客户端及连接配置 | 每个 Notify 批次创建一个客户端，号码间顺序复用；SDK Transport 使用共享连接池 | N 个号码的客户端构造降为 1；不同调用的连接可复用，凭据和 context 不共享 |
| SDK 自身请求没有绑定业务取消 | 传输包装同时保留 http.Client 超时及上游取消 | 等待响应头、读响应体都能中断，不用“后台请求继续跑”的超时 goroutine |
| SDK/腾讯返回体未限制 | 最大读取 64 KiB + 1 字节用于判定超限；关闭真实响应体，再给 SDK 有界数据 | 防止异常应答无限占用内存，成功短应答可复用连接 |
| 云通信只看 err 或 Message 文本 | 阿里云检查 Code=OK；腾讯检查显式整数 result=0；短信进一步校验逐号码 detail | 拒绝空响应、误含 success 的失败响应、部分号码失败及不完整回执 |
| 同批结果/日志按号码和全文累积 | 汇总 accepted / failed / notAttempted，保留首个错误；移除电话号码与消息全文的重复日志 | 结果空间不随号码数量增长；部分成功和取消后的未尝试数量不会伪装成成功 |

SDK 不随意替换版本，不改服务商、签名协议、模板或配置字段。新增小型 `pkg/medium/delivery` 只承载四个云通信实现共用的预算、结果校验和批次汇总，不引入队列产品或通用任务框架。

## 时间与重试语义

- **每个号码请求最多 10 秒**，若调用方更早取消/超时，使用更早期限。
- 整批保持可取消，但不设置固定 30 秒整批截断：否则大名单的尾部号码可能每轮都无法被处理。本地新增用例证明前一个号码超时不会耗尽后续号码预算。
- 本批仍顺序处理名单；最坏批次耗时仍与号码数相关，尚不能称为已完成通知调度优化。后续有界调度需要与状态更新、重发和恢复事件持久化一起设计。
- 阿里云原 SDK 默认关闭自动重试；现在显式配置 `AutoRetry=false`、`MaxRetryTime=0`，并有调用次数回归。没有新增超时重发机制。
- 已受理只表示服务商接受请求，不等于短信送达或电话接听；最终送达需服务商回执，当前系统没有新增回执消费。
- 超时或读取失败可能发生在服务商已受理之后，归类为“失败或结果未知”。不要自动重放整批，避免重复短信、电话及费用。
- 兼容历史直接调用的 Post/Call 方法签名；应用内部改用 typed error，不再分析 Call 返回字符串中的 success。
- 内部 NotificationResult.Data 从逐号码字符串列表改为三个汇总计数。代码检索确认使用方只有两个适配器，不属于前后端 API 契约；页面测试失败仍使用原有错误响应结构。

## 验证

已通过：

1. 四类 provider 正常受理、业务拒绝、HTTP 500、缺失结果码、超限应答，以及取消后不发送下一号码。
2. 真实阿里云 SDK 的请求生成/解码与传输包装；网络层替换为隔离模拟响应，没有访问实际云 API。对两号码批次验证恰好两次尝试，失败不触发 SDK 重试。
3. 共用 Transport 使用本地 HTTP 服务验证：保留 client timeout；父 context 可取消 headers/body 等待；取消后服务端确认连接请求结束。
4. 三个独立 HTTP 客户端顺序请求，复用一个 TCP 连接；超限回执失败，不给 SDK 无上限数据。
5. 部分成功、取消未尝试数量、全空号码、nil 消息/结果、明确错误码与敏感错误文本不回显。
6. 一个号码超时后，后续号码获得独立预算并继续处理，没有尾部饥饿。
7. `go test ./pkg/medium/... -count=10 -timeout 120s` 通过。
8. 后端相关包非缓存测试与二进制构建通过。测试范围同前批：cmd、alert、internal、api、client、tools、provider、medium、oidc；未执行包含固定私网服务地址的 provider/test 示例。

未进行真实短信、电话、生产部署或容器压测；本机无 Go race 所需的 C 工具链，未宣称 race 验证通过。本地成功不能证明账号套餐、模板审核、号码授权或真实投递成功。

## 官方协议核实与独立遗留问题

本次通过 agent-reach 的 Exa 检索核对官方文档，结果校验以字段含义为准，不根据英文提示文本猜测：

- [腾讯指定模板群发短信](https://cloud.tencent.com/document/product/382/5977)：顶层 result 与 detail 中的逐号码 result；本实现保守地将缺少完整号码回执视为未确认，不自动重试。
- [腾讯指定模板语音通知](https://cloud.tencent.com/document/api/1128/37723)：result 用于判断请求结果；请求模板字段为 tpl_id/params。
- [阿里云 SingleCallByTts](https://help.aliyun.com/zh/vms/developer-reference/api-dyvmsapi-2017-05-25-singlecallbytts)：Code=OK 表示请求成功，Message 为描述；不是接听结果。

**已确认待修的腾讯语音兼容性问题：** 当前 `/sendtvoice` 调用构造 `prompttype/promptfile`，系统模型只提供 SecretID/SecretKey/AppID，没有该接口需要的模板 ID。另有旧 AppKey 与新式 SecretKey 字段命名混用风险。本批仅增加取消和明确失败结果，没有假装该请求协议已修好或已能真实投递。已向用户询问是否正在使用腾讯电话及是否授权配置/接口调整；该选择不阻塞其他性能优化。
