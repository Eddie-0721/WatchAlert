## 本批变化

1. 评估结果区分完整、失败与截断。任一数据源失败/禁用/丢失/类型不匹配/跨租户引用/工作协程异常时，整条规则跳过恢复判定；完整空结果仍按现有恢复等待时间处理。
2. Prometheus warnings、非向量响应及 NaN/Inf 不再当作健康空结果。超过 1000 条结果时可处理已取回的正向告警，但不能依据截断结果恢复。CloudWatch 的接口失败、部分结果、未读完分页及非有限值不再静默忽略；无指标样本保守视为不能判断。
3. 失败后重新获得完整结果，或者评估器重启后，重新开始待恢复等待窗口；窗口写入失败不会允许后续沿用旧时间恢复。恢复只匹配当前租户和完整规则 ID，不做子串匹配。
4. 静默创建/更新的数据库保存与缓存同步分开报错。已保存但缓存未确认时提示对象 ID，不提示操作完全成功。删除使用服务端存储的故障中心，不信任页面传来的中心；数据库删除失败尝试回补缓存。
5. 启动加载静默从“最多 1000 条”改为稳定分页、串行加载，并报告加载中途失败，避免无条件成功日志和批量创建无界协程。
6. 认领检查告警身份、恢复状态和缓存写入结果，去重，单次最多 500 条；部分失败返回已认领/未确认数量，不能报全部成功。已认领告警不覆盖原负责人。此处未实现跨实例原子竞争认领。
7. Agent 精确查询按指纹、可选故障中心定位，查不到或存在歧义返回错误；继续使用可信租户、数据源及环境范围过滤。相关告警注明关联依据、候选上限与是否截断，不宣称已确认为同一故障。
8. Agent 写操作结束后检查执行记录持久化结果。记录未确认时返回“可能已生效、勿重复执行”，不允许同一操作重新确认。失败状态不代表所有副作用已回滚。
9. 前端静默删除不吞错误，确认中禁用重复按钮，删除后保留筛选；列表失败可重试，合法 null 空列表兼容，搜索提交后请求，旧列表请求不覆盖新筛选响应。告警认领失败展示后端说明，不假装成功，不同时修改其他故障中心的同指纹行。

### 有意保留的边界

- 一个数据源出错会延缓同规则其他数据源的恢复，这是本批保守策略。数据源级指纹迁移、独立恢复状态需要兼容设计，未在此批更改已有告警身份。
- 尚无持久化的规则评估健康状态展示；运维仍需结合后端失败日志查看为何暂停恢复。CloudWatch 健康检查占位及各类 NoData 策略仍需后续处理。
- 静默 DB/Redis 并非原子事务；服务重启、并发更新/删除、消费者缓存刷新竞争仍需一致性对账与真实 Redis 联调。本批不宣称静默全链路一致性已完成。
- 认领仍是读后写缓存；并发抢占、其他写入方覆盖、消费者事件状态竞争尚未做多实例验证。部分批次成功无法自动撤销。
- Agent 的未知执行结果尚无自动对账，必须按操作 ID 和目标对象核对，不应重新生成同样的写操作“试一下”。工具审计可靠投递、敏感日志与外部目的地址策略仍在 R1/R4 待办中。
- 没有增加 AI 权限或自动执行能力；全站 UX 重构、包体积拆分未纳入本小批。

## 构建步骤（在你们的 Linux 构建机执行）

先确认工作区干净；存在服务器本地 Dockerfile 改动时先检查和保留，不能 reset 或强制覆盖。下面命令须在各自仓库目录执行，任何一步失败即停止。

后端：

```bash
git status --short
git fetch origin
git switch eddie
git pull --ff-only origin eddie
BACKEND_REV=$(git rev-parse --short HEAD)
docker build --build-arg VERSION="$BACKEND_REV" -t "harbor.guardforceai.cn/other/watchalert:r2-$BACKEND_REV" .
docker push "harbor.guardforceai.cn/other/watchalert:r2-$BACKEND_REV"
```

前端：

```bash
git status --short
git fetch origin
git switch eddie
git pull --ff-only origin eddie
WEB_REV=$(git rev-parse --short HEAD)
docker build --build-arg NPM_REGISTRY=https://registry.npmmirror.com -t "harbor.guardforceai.cn/other/watchalert-web:r2-$WEB_REV" .
docker push "harbor.guardforceai.cn/other/watchalert-web:r2-$WEB_REV"
```

后端已配置国内 Go/Alpine 软件源，前端使用 npm 镜像。基础镜像仍需要构建机可以拉取；若 Docker Hub 不可达，先在内部仓库准备已核验基础镜像。前端可通过 NODE_IMAGE、NGINX_IMAGE 参数指定内部镜像，后端尚无同类参数，不虚构可用的内部镜像名称。本次不改锁文件或升级依赖来绕过网络问题。

## 生产发布与低风险验收

1. **发布前记录**：当前 Kubernetes context、namespace、Deployment/容器名、两端实际旧镜像 digest、后端副本数、当前错误率/活跃告警/静默数量；备份数据库，并保留配置、Secret 的原版本（不要把内容写入 Git）。历史对话中的 monitoring/w8t-service/w8t-web 不是对当前集群状态的核验。
2. **配套部署**：记录构建产物 digest，在低风险时段更新后端与前端，Agent 保持当前镜像。若后端已有多副本评估，先核实去重机制；不要为“灰度”直接增加评估副本，避免重复通知。两端更新存在短暂混跑，期间避免编辑凭据和执行 Agent 写操作。
3. **账号密码验收**：管理员及普通成员正常登录；无权限操作拒绝且不产生副作用；浏览器不返回秘密字段；不要在生产修改既有数据源密钥或连接地址进行试验。
4. **只读验收**：告警列表/详情可识别环境、服务与负责人；静默列表筛选、搜索、分页正常；现有活动告警与通知情况和发布前相符。真实查询超时若自然发生，核对日志及事件没有误恢复；不人为制造生产数据源超时。
5. **写流程验收**：先明确一个专用测试故障中心/测试告警及不会匹配真实业务的标签。只在此对象做认领、短时静默预览/确认/删除，并核对数据库、缓存及通知效果；未确定对象前不测试写操作。
6. **AI 验收**：有权限账号从明确告警进入 Copilot，核对工具返回指纹和证据；无数据时不得编造故障结论。外部模型调用涉及数据出站和费用，继续使用现有审批及脱敏规则。写权限默认不扩大，不把模型回答当执行结果。
7. **观察并签收**：持续观察至少两个评估周期并覆盖该故障中心恢复等待时间、一个静默生效/到期窗口；核对实际通知。记录版本、时间、操作者和逐项结果；失败项不能勾选为已通过。

## 回滚条件与做法

- 明显告警误恢复、通知中断或重复、正常登录不可用、权限越界、模型凭据读取失败，立即停止扩大验证，记录证据并按维护窗口回滚配套前后端。
- 使用发布前记录的**实际旧镜像 digest**恢复两个 Deployment，不能把旧 Git SHA 当成生产镜像已存在的证明。不要删除数据库/Redis，不清空待恢复数据，不批量重建告警。
- 本批未新增数据库结构迁移，但前置安全版本含配置/凭据处理变化；回滚代码不会撤销运行期间的静默、认领或凭据修改。配置与业务数据的恢复需要逐项核对，不能直接覆盖新业务数据。
- 不轮换/重置 Agent credentialKey；更换该密钥可能导致已有模型密文不可读。不要在终端或报告中输出 Secret 内容。
- 旧版本包含本批已修复问题，回滚是止损，不是长期方案；保留候选分支与提交用于修复后重发。
