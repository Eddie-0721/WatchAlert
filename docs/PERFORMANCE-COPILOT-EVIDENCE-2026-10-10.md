# Copilot 历史证据读取优化

日期：2026-10-10。后端基线 `400b81f`；本批只修改 Go 后端，前端与独立 Agent 不变。

## 已复现问题

`internal/services/agent_session_page.go` 将每条历史 Evidence 完整解码为嵌套 `map[string]interface{}`，随后无条件重新序列化。即使没有待更新操作，也会拆解并重写查询结果、预览和来源数据。

修改前回归测试确认：`9007199254740993` 被转换成 `9007199254740992`，`1.2300` 被改写成 `1.23`。这是后端接口返回值的变化，历史数据库原文未改变。

## 实现与边界

- 使用 `json.RawMessage` 保留嵌套字段，只读取准确大小写的 `actionId` 和 `status`；不使用大小写不敏感的结构体字段匹配。
- 仍按当前租户、会话及本页实际引用 ID 查询操作状态，每批最多 100 个去重 ID，保留过期判断和访问权限。
- 只有权威操作状态实际变化才重新编码 Evidence；无变化时原文逐字节保留。重新编码时嵌套数值不经过浮点数转换，但空白和字段顺序可能改变。
- 无效 JSON、错误数组结构、空值、非字符串 ID、未知操作及跨租户/会话引用保持原处理边界。合法超大 JSON 数值不再因 float64 范围而阻止状态更新。
- 请求取消在消息解析/覆盖前及返回前检查，不声称可以中断单次正在执行的 JSON 解码。
- 不写回历史、不变更接口形状、分页、模型调用或权限；不修复浏览器 JavaScript 自身的数值精度限制。

## 本地对照测量

Windows / Go 1.24.11 / Ryzen 7 7700；真实 GetSession 服务 + 内存 SQLite。每页 50 条消息，每条包含 100 个嵌套合成样本，三轮各一秒。数据构造不计时，数据库读取、状态查询及证据处理计时。

| 场景 | 修改前耗时 | 修改后耗时 | 修改前临时分配 | 修改后临时分配 |
|---|---:|---:|---:|---:|
| 无操作状态更新 | 8.93–9.16 ms | 3.515–3.529 ms | 9.49 MB | 2.29 MB |
| 每条均需覆盖操作状态 | 8.97–10.03 ms | 5.37–5.64 ms | 9.51 MB | 3.42 MB |

分配分别降低约 76% 和 64%，是每次操作的累计临时分配，不是进程常驻内存。此 fixture 用于嵌套证据容量对照；独立 Agent 当前 `source.records` 只保留前 10 条标识，不能把这个较大的合成场景当作典型线上载荷或生产延迟结论。

复现/测量入口：

```powershell
go test ./internal/services -run '^TestSession(Page|Evidence)' -count=10 -timeout 120s
go test ./internal/services -run '^$' -bench '^BenchmarkSessionEvidencePage$' -benchmem -benchtime=1s -count=3
```

## 验证与发布

- 大整数及小数词法保留、未知字段、原始数据库记录不变。
- 无需覆盖的 JSON 原文、无效证据、null 项、非字符串及错误大小写 ID、跨租户/会话隔离。
- 205 个不同操作及重复引用分三批读取、错误类型旧状态可覆盖、极大 JSON 数值保留。
- 历史查询完成后的取消，以及既有分页、并发追加、过期操作和权限用例，连续 10 次通过。
- 后端相关包测试、静态检查及构建通过；本批没有前端/Agent 修改，未重复浏览器验证，未调用真实模型或部署生产。

仅需更新后端镜像；无新增配置、依赖和数据库迁移。可回滚到本批前版本，但旧版证据重写问题会恢复。当前历史仍需读取每页 Evidence 原文，单条证据大小未在本批进一步限制；真实数据库/生产容量、流式 done 早于落库及其他整体优化待办仍未完成。
