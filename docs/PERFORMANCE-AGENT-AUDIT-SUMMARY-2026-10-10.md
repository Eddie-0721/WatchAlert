# 工具审计摘要复制与 UTF-8 边界

日期：2026-10-10。后端基线 `4fc0474`；仅后端变更。

## 实际问题

工具审计原先执行 `truncateToolResult(string(output))`，先把完整 JSON 字节转换为字符串，再截取 32 KiB 摘要。对大结果发生一次不必要的完整字符串分配。按固定字节截断也可能切在中文/emoji 中间；修改前测试已复现 3/4 字节字符的各个中间位置得到无效 UTF-8。

## 修改

- 摘要函数直接接受 JSON 字节，只复制保留的前缀；不转换整份大结果为字符串。
- 超过 32 KiB 时回退至最后一个完整 UTF-8 字符边界，再添加原有省略号；不会因边界截断写入无效 UTF-8。
- 小结果逐字节保留。大结果仍是至多 32 KiB 的内容前缀加省略号（省略号本身 3 字节），不新增字段、不删除审计输入或改变完成/失败状态。
- 完整结果仍返回调用方，输入与持久化策略不变；不增加缓存、后台任务、依赖或自定义 JSON 编码器。

摘要函数输入来自标准 JSON Marshal，其输出保证合法 UTF-8；函数不是任意不可信二进制的 Unicode 清洗器。摘要仍是可能截断的 JSON 文本片段，而非保证合法完整 JSON 文档，与之前用途一致。

## 测量

Windows / Go 1.24.11 / Ryzen 7 7700，三个一秒样本。对照原字符串转换+截断和修复后的实际函数。输入字节预先生成，仅测摘要复制，不包括 JSON 编码、数据库、HTTP 或模型。

| 已编码输入 | 原耗时 | 新耗时 | 原分配/次 | 新分配/次 |
|---|---:|---:|---:|---:|
| 128 B | 21.49–22.00 ns | 21.10–21.82 ns | 128 B | 128 B |
| 32 KiB | 1.86–1.92 µs | 1.89–1.93 µs | 32,768 B | 32,768 B |
| 2 MiB | 100.89–102.56 µs | 1.91–2.03 µs | 2,138,120 B | 40,960 B |

**大结果仅摘要复制阶段**少约 2 MiB 分配，不是整个工具请求或进程内存的降幅。当前调用方会因自身网关字节预算拒绝部分大结果，2 MiB 是用于观察该阶段开销的合成边界数据，不代表正常请求大小。

## 验证

- 修改前复现中文/emoji 截断无效 UTF-8，修复后通过。
- 空、小、恰好上限、上限+1、2 MiB；2/3/4 字节字符边界、源字节不变、结果不引用可变输入。
- 完整 Execute + SQLite 用例：大中文规则描述完整返回，仅审计 Result 是摘要，Input 和状态不变。
- 专项连续 10 次，以及后端相关包测试、静态检查和构建通过。
