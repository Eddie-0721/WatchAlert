# Agent 内部响应读取的有界拼接

日期：2026-10-10。后端基线 `7338d2f`，本批仅修改 Go BFF，不修改独立 `WatchAlert-agent` 仓库、前端或模型配置。

## 已复现问题

后端 `callAgentServiceStream` 原实现只设置 Scanner 单行 2 MiB 限制，多个 `data:` 行使用 `data += part` 累积：

1. 每次都复制此前内容，多段长事件产生二次方级别的累计复制。
2. 单行没超限但合并超过 2 MiB 的事件仍会被接受；小事件/注释组成的长流也没有字节总预算。
3. 非流式读取使用 LimitReader 截到 2 MiB 后直接解析。有效 JSON 后跟大量空白时，超限响应可能被当作有效结果接受，没有截断错误。

修改前真实本地 HTTP 测试复现：超大多行 done 被接受；超大 JSON+空白被静默截断后接受。修改后两例都明确失败。

## 改动与边界

- 拆出 `agent_transport.go`，使用有界拼接缓冲。正常单 data 行直接保留片段，不额外创建拼接缓冲；只有多片段事件使用 Builder，避免反复复制已有内容。
- 保持现有内部协议的片段 trim/直接连接语义，不顺带改造成通用 SSE 标准解析器。独立 Agent 当前发送单行 JSON，协议不变。
- 保留单行 Scanner 2 MiB 上限，新增**合并事件数据 2 MiB**上限，以及**整次流响应 8 MiB**预算（含状态帧、注释、分隔符等）。单行还包含字段前缀，实际单行 JSON 可用字节略少于 2 MiB；这与原 Scanner 行限制一致。
- 非流式及 HTTP 错误响应读取至多 2 MiB+1，明确辨别超限，不把截断前缀交给成功解析。
- 读取/分发缓冲事件前后检查取消；沿用 HTTP 请求 context、超时、关闭 response body，已取消请求不继续分发已缓冲的后续事件。
- 超限返回错误而非静默截断。`StreamMessage` 收到错误仍走原失败路径，不保存该次 assistant 回复；已发出的部分文本由既有前端错误处理展示，不是完成的分析。

2/8 MiB 都是内部传输安全预算，不是 token 计费或浏览器历史容量。模型当前最多 8 轮、单轮输出 4096 token，并另有工具内容预算；本批不调整这些限制，也不扩大权限或写操作能力。若未来需要明显更大的合法响应，应一起评估预算和消费者，不能默认无限累积。

## 测量

`BenchmarkAgentStreamAssembly`：Windows / Go 1.24.11 / Ryzen 7 7700，三轮各一秒。构造 256 KiB 内容、每片段 256 字节的内部多行事件，对比原 immutable 拼接+JSON 解码和新的完整解析路径，不含网络/模型/数据库。

|实现|耗时|临时分配/操作|
|---|---:|---:|
|原多片段累积|9.07–9.26 ms|139.37 MB|
|有界缓冲|0.926–0.943 ms|2.02 MB|

这是用于暴露拼接放大的边界场景，**不是正常单行 Agent 帧的耗时收益，也不是生产 AI 回复提速比例**。正常模型推理延迟、网络耗时不由此基准证明。按原协议拆分 JSON 字符串的 fixture 只用于兼容性/性能对照，不代表推荐其他 SSE 服务使用此格式。

## 验证

- 两个修改前失败、修改后通过的 HTTP 超限复现。
- 普通 status/delta/done、证据、中文、keepalive、多行片段、EOF 无空行，内容和事件顺序保留。
- 非流式正常 HTTP 请求/内部令牌透传；2 MiB 响应的上下边界。
- 合并事件恰好 2 MiB 可解析；合并超限及单行超限失败。
- 多个小帧/注释不能绕过 8 MiB；恰好总量通过，多一字节（包括 done 后的尾部）失败。
- 无 done、空 done、坏 JSON、Agent error 继续失败；已取消请求不读取，分发后取消不继续发缓冲 done。
- 真实本地 HTTP 中断取消上游等待，没有真实模型/网关调用。
- 专项连续十次、相关后端包回归、go vet 和全项目构建通过。无前端修改，本批未重跑浏览器；无生产部署，Windows 无 CGO race 检查条件。

## 发布与后续

只需更新后端镜像，前端和独立 Agent 无需配套升级。没有配置/数据库变更，可独立回滚；回滚会恢复上述传输边界缺陷。

本批不改变 done 的既有发送时机。代码审查另外确认 `StreamMessage` 在回复落库前透传 done；若随后数据库失败，客户端会先收到 done 再收到 error。完成状态与落库顺序属于另一个可靠性问题，需独立处理和验证，不能因本批通过就声称已修复。

整体性能目标仍未完成：历史消息字节容量、实际数据库/Redis 容量、底层 Redis 取消、告警全量读取等既有待办继续保留。
