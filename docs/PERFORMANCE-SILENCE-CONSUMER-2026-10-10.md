# 通知消费者静默热路径优化（2026-10-10）

基线后端 `5d0cc1c`；分支 `codex/performance-silence-consumer`。本批只处理静默读取、生命周期状态同步及运行时缓存，不并行发送通知，不改变通知聚合规则。

## 已实施

1. 单次通知静默判断由 HGETALL 获取 ID 后逐条 HGET，改为一次读取并解析；不跨判断缓存结果，下一次判断可看到刚编辑的规则。
2. 每秒状态同步同样只读一次。未来/生效中但状态未变化的规则不再写 SQL 和 Redis。
3. 自动同步只更新数据库 `status` 列，并匹配租户、ID、故障中心、起止时间和配置更新时间；不会把快照中的旧标签、备注写回数据库。已成功写 SQL、但缓存同步失败的状态可以重试。
4. Redis 比对读取时的原始 JSON 再原子更新；格式/字段顺序不同的历史 JSON 也可以处理。若规则已被编辑或删除，比对失败就不覆盖、不复活。Lua 不解码/重编码 JSON，避免把空标签数组变成对象。
5. 数据库确认过期后，原值匹配的缓存项被移出；数据库历史记录保留。启动不再把数据库 `status=2` 的历史加载回热缓存；时间已过但 SQL 尚未标记过期的记录仍加载，交给消费者完成状态迁移。
6. 生命周期 SQL 查询使用消费者的取消信号和每次 10 秒预算。取消后停止后续状态写入；这不代表所有通知发送和 Redis 调用已完全支持取消。

## 验证证据

- 1,000 条未变化规则：一次缓存读取、零 SQL/缓存写入；另外加入开始生效、过期、旧过期缓存三种情况，只处理发生变化/需清理的项；第二轮无重复写入。
- 1,000 条真实编码缓存项的读取测试，记录到 1 条 Redis 命令。
- 20 个并发 CAS 使用同一个旧快照，只有 1 个成功；并发编辑保持不变，删除后不会被旧快照重新建立。
- 比较原始带缩进 JSON；成功转换后标签仍是数组。过期清理只移除目标项，不影响其他规则。
- SQLite 验证仅状态列变化、同一秒修改备注不被覆盖、时间/中心变更保护、租户隔离、取消与缓存失败后的 SQL 重试。
- 启动分页仍覆盖超过 1,000 条规则；2,501 条混合历史中只加载 1,250 条非过期状态，仍读取全部 3 页，不因跳过项提前结束。
- 新增测试依赖 miniredis v2.33.0（沿用原依赖图已有版本）和其 Lua 解释器，在本地隔离服务中执行 CAS 脚本；不连接生产 Redis。它只被 `_test.go` 引用，不进入服务二进制。
- cache/repo/services/mute/consumer 回归连续 10 次通过，相关全后端非缓存测试通过。本地模拟器不等于真实 Redis ACL/集群验证，SQLite 不等于生产 MySQL 负载测试；没有执行 race detector。

## 发布与回滚

仅更新后端，无前端/Agent 修改，不更改 SQL 表结构、API 返回字段或已有缓存 key 格式。Redis ACL 需要允许 `EVALSHA`/`EVAL` 以及原有哈希操作；受限账户应先核验权限。脚本执行失败会记录状态同步错误，不能据此声称静默已经成功同步。

过期缓存移除不是删除用户历史数据；SQL 记录仍在，可查询/重新加载。回滚旧镜像不需要数据迁移，旧版本启动可能重新加载这些过期记录，性能收益会消失。

本批未部署、未更改生产 ACL、未清理生产数据。后端二进制构建和差异检查通过后按既有约定合入 `eddie`。

## 未完成项

- 当前通知/升级仍然逐事件判断静默；本批消除的是每次判断中的额外 HGET，不是把一轮全部事件压成一次读取。后续发送调度需进一步优化，同时避免长时间复用静态快照导致新静默不生效。
- 原有静默读取失败返回“不匹配”的发送策略尚未更改；需要与发送状态记录、聚合时间戳一起处理，不能只改布尔值就宣称可靠性修复完成。
- DB 与 Redis 不是跨存储事务；API 写入失败后的对账、旧版本滚动运行时的无条件写回仍属于剩余边界。新消费者 CAS 不代表所有旧写路径都支持版本比较。
- 慢通知、共享事件对象、LastSendTime 写入时机以及消费者重复启动/停止仍待下一批处理。本批没有通过直接并发调用原发送函数来掩盖这些问题。
