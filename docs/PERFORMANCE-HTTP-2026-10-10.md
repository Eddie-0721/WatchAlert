# HTTP 查询与连接复用优化（2026-10-10）

基线后端 `bc6e872`；工作分支 `codex/performance-provider`。仅后端变更，无新的模型调用、前端交互、数据迁移或生产操作。

## 已修复

- 通用 GET/POST 不再每次创建独立 Transport。共享有界空闲连接池（全局 100、每主机 10、空闲 90 秒），请求头、客户端超时均独立，不共享 CookieJar。非正超时使用 10 秒，不再无期限等待；正值沿用调用方配置。
- 增加 context 请求入口。Loki、VictoriaLogs、Jaeger 的规则查询以及数据源指标代理请求可以取消；构造无效 URL 时先检查错误，避免设置 nil 请求头导致 panic。
- 三类查询统一校验 HTTP 200、读取完整性与 8 MiB 解压后响应预算。失败不返回成功空结果，不记录上游错误正文。预算超限显式报错，不截取部分正文后继续评估。
- Loki 校验成功状态和 streams 结果，修复缺省时间参数的类型断言问题；VictoriaLogs 检查每行解析与 scanner 错误，支持预算内超过原 64 KiB 的单行；Jaeger 检查返回 errors/数据结构/trace ID，保留显式 `data:null` 的空结果兼容。
- Loki、VictoriaLogs、Jaeger 不再在每次规则评估前额外请求健康接口；Jaeger 构造函数不再执行一次额外 GET。显式“测试连接”仍可用。Elasticsearch、SLS、ClickHouse 等前置检查仍保留，未盲目移除。
- 补齐上述 provider、Elasticsearch 连接检查、通知渠道、OIDC、Grafana/指标代理相关响应的关闭。Webhook/SREFlow 成功响应只排空最多 4 KiB，以支持小响应连接复用，不无限吞掉正文。
- SSL 证书探测走不复用连接的专用入口。否则共享连接可能令证书探测读取旧 TLS 握手的证书，并把复用耗时误记为握手耗时。

## 本地验证与可量化结果

- 真实本地 HTTP 服务验证不同认证头的 3 个连续 POST 仅建立 1 个 TCP 连接，且不发送前一请求设置的 Cookie；2 次强制新连接请求额外建立 2 个连接。
- 6 类通知渠道分别连续发送 3 次请求，验证小响应路径仅建立 1 个连接。不向真实通知平台发消息。
- Loki、VictoriaLogs、Jaeger 规则评估测试：每次只有 1 个实际查询，不出现构造/健康请求；上游 503 即便正文类似空结果也返回失败。
- 覆盖成功空结果、错误状态、缺失结构、无效 JSON 行、超过 64 KiB 单行、读取截断、取消、8 MiB 边界及所有返回路径关闭响应。
- 相关工具/provider/评估测试重复 3 次通过；不将本地连接计数等同于生产吞吐提升比例。
- `go test ./alert/... ./internal/... ./api/... ./pkg/client ./pkg/tools ./pkg/provider ./pkg/medium/... ./pkg/oidc -count=1 -timeout 120s`、后端二进制构建及差异格式检查通过。

## 保留边界与后续

- 本批**保留既有通用请求跳过 TLS 证书校验的行为**，并未声称安全性问题已经解决。切换为验证证书需要梳理自签名 CA/配置与连接测试，避免性能发布同时中断用户数据源。
- 8 MiB 限制适用于本批三类日志/链路 HTTP 查询，并非所有上游调用已统一限额。大型合法查询应缩小时间范围/筛选结果，超限不会被视为告警恢复。
- 上游返回配置 limit 数量时的语义完整性、日志计数准确性、Loki 评估端时间单位、Jaeger 默认时间单位仍需单独核实。此次保护涵盖 HTTP/协议解析失败，不声称解决全部日志/链路误恢复风险。
- 旧 AI 客户端、云 SDK、Elasticsearch/ClickHouse 客户端生命周期和取消，以及部分通知响应的无界正文读取仍需继续处理；不能因共享 Transport 就认定所有资源泄漏已消失。
- 没有运行 `pkg/provider/test` 下带固定内网目标/本机 Kubernetes 配置的历史集成示例；未访问这些目标、未用生产数据、未测试真实云服务、未构建或部署容器。前端无修改，本批不包含浏览器验收。
- 服务响应契约不变，无数据库迁移。只需更新后端镜像；回滚到前一后端镜像即可。若日志/链路超过预算会收到查询失败，需要先查看评估错误，而不是把保留的旧告警解释为新告警。
