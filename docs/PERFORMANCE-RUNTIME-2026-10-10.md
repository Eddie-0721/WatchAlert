# 性能优化：运行预算与 Copilot 渲染

## 范围与状态

第二批，基于后端 `3c4609c`、前端 `0d66824`、独立 Agent `04e5599`。
三个仓库在 `codex/performance-runtime` 开发。本文件记录本地验证结果，不表示已部署或已完成全部系统性能优化。

## 已完成

| 仓库 | 修复 | 边界与兼容性 |
|---|---|---|
| 后端 | Agent 查询 Prometheus 时传递请求取消；读取响应前限制 4 MiB，总样本最多 1000，范围查询计算包含结束点并拒绝非法 step | 超限/部分结果返回错误，不将失败当作空结果或恢复；规则评估未套用 Agent 的 1000 样本限制 |
| 后端 | Prometheus provider 复用 HTTP 连接池；鉴权头按请求注入、不修改原请求 | 本地服务验证两个不同凭据使用同一连接但不串凭据 |
| 后端 | 模型运行前仅读取最新 11 条历史（随后附加本次用户消息），SQL 不取 evidence，单条最多 8000 字符、合计 24000 字符 | 原始完整消息及证据仍存储；会话详情接口未改为分页，数据库排序成本还需索引阶段处理 |
| Agent | 每进程最多 8 次分析、总时限 50 秒，拒绝无限排队；模型单请求 40 秒、自动重试 0、单轮输出 4096 token | 可通过环境变量调整并发与总时限；后端超时须预留至少 5 秒；副本/worker 数量影响总并发 |
| Agent | 查询和操作预览共用 10 次 Tool 预算；同轮并行相同调用去重；连接在正常、失败、超时、取消时关闭 | 缓存仅当前运行可见；静默/认领仍然必须经后端授权和用户确认 |
| Agent | 输入历史、工具响应字节及模型可见结果长度设限；超限明确失败 | Tool 响应最多 512 KiB，单结果 24000 字符、合计成功结果 48000 字符；字符限制不等于准确 token 成本 |
| 前端 | 流式文本合并为每 50ms 至多一次定时更新；最终回复立即显示，失败保留已经收到的部分内容 | SSE 解析仍逐事件，不丢弃文本；最终回复不会被旧定时器覆盖 |
| 前端 | Markdown 内容 memo 化、取消 effect 二次渲染；只加载 8 种常用代码高亮 | bash/JSON/YAML/SQL/Go/Python/JS/TS；其他语言保持纯文本可读，不保证原高亮 |

前端同构建环境产物比较：Markdown JS chunk 从约 **755 KB / gzip 267 KB** 降至 **188 KB / gzip 62 KB**。这是该 chunk 的文件体积，不是全站首屏体积，也不是生产延迟改善比例。入口约 881 KB、Monaco 约 3.32 MB 的现存大包警告仍保留。

Agent 资源管理核对了 [OpenAI 官方运行文档](https://developers.openai.com/api/docs/guides/agents/running-agents) 和实际安装的 SDK 源码；按 `cancel()` 后消费结束事件的接口处理流式后台任务。运行测试使用 Python 3.12.9 / openai-agents 0.21.1 / openai 3.27.0，安装在忽略的 `.venv-perf` 中，没有提交或更改依赖版本范围。

## 验证

- 后端：`go test ./pkg/provider ./internal/services ./internal/repo ./internal/cache ./alert/eval ./alert/consumer ./api -timeout 90s` 通过；consumer 当前无测试文件。
- 新增 Go 用例覆盖响应字节、总样本、部分结果、取消到达上游、连接复用与凭据隔离；SQLite 验证有限历史读取、长度边界、租户/会话所有者隔离和取消。
- Agent：Python 3.12 运行 25 项 unittest、compileall 通过；包含过载拒绝、取消释放、总超时、SDK 客户端关闭、工具去重及累计上下文预算。模型输出和网关使用测试数据，不调用付费模型。
- 前端：18 项单元测试、TypeScript 检查和 Vite 生产构建通过；12 项 Chromium 浏览器回归通过，覆盖千段快速输出后的 done/error、代码块可读性、历史证据桌面/手机、告警现场往返、首页请求数量和编辑器按需加载。
- 浏览器接口为 fixture，未连接生产数据源。未执行生产压测、Docker/Kubernetes 部署、真实模型性能测试，不能推导生产 p95、并发容量或费用下降比例。

## 部署与回滚

- 三个镜像分别构建；本批没有数据库 schema 迁移、权限新增或请求字段协议变化。前后端沿用 `eddie`，Agent 沿用 `main`。
- Agent 新配置可不填，默认生效。若生产后端 `Agent.timeout` 小于 60 秒，应把 Agent 总时限相应设小，避免后端先断开；提高时限不等于增加处理能力。
- 先检查 readiness、普通告警/规则页面，再验证一条小范围 Prometheus 分析、一次主动停止、历史会话恢复，以及操作预览仍需要确认。不以真实生产静默/删规则进行性能测试。
- 回滚恢复原镜像标签即可；不删除会话记录。只有部署后采集的延迟、错误率、RSS、CPU和模型用量能证明生产收益。
