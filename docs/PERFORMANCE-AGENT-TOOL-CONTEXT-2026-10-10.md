# Agent 只读工具取消与审计等待上限

日期：2026-10-10。后端基线 `e60face`；仅后端变更。

## 问题依据

工具网关虽接收 request context，但能力查询走无 context 入口，规则/故障中心/静默/数据源读取也会丢弃取消信号。Prometheus HTTP 请求已支持取消，其前面的数据库数据源读取却没有传递。每个工具的 deferred 审计写入没有期限，可能在工具完成或请求断开后继续等待连接。

## 本批改动

- 增加 `CapabilitiesContext`，浏览器能力接口与工具网关使用请求 context，沿用上一批配置/权限查询的 10 秒预算。旧方法保留供未迁移调用者使用。
- 规则详情/PromQL、故障中心详情、静默查询、数据源列表与 Prometheus 查询前的数据源读取传递取消；数据库查询阶段最多 10 秒。既有 Prometheus 网络查询预算不变。
- 故障中心、静默服务和相关仓库增加 context 入口，复用同一过滤和分页逻辑，不重新实现业务条件。旧服务 `Get`/`List` 包装入口也使用新增 10 秒预算；旧仓库入口继续以 Background 兼容原调用。
- 审计同步尝试保存，使用独立的 10 秒 context；不会因为用户断开就直接跳过失败审计，也不创建后台协程/队列或重试。
- 审计失败增加仅包含本次内部 call ID 的应用错误日志，不把原始 SQL、工具入参、结果或底层错误拼进新增日志。数据库驱动/全局日志的内容不是本批审计范围。
- 保持原 best-effort 审计语义：失败不覆盖已经产生的查询结果或工具错误，不声称记录一定持久化。要实现强制审计/持久化队列需要独立设计，不能悄悄通过自动重跑工具补记录。

## 验证

专项连续 10 次通过：

- 正常规则查询与已取消请求分别产生 completed/failed 审计，审计 context 不随请求取消且有截止时间。
- 审计写入错误仍可观测，保留原只读工具结果；无自动重试。
- 六条工具读取路径检查 context 转发，模型提供的 tenantId 不覆盖授权租户，静默页大小仍限制 50。
- 真实 SQLite 仓库验证两租户隔离、数据源单/多类型与搜索、故障中心 ID/名称、静默过滤及第二页/总数。
- 占满连接池时四类仓库读取按调用方 30ms 截止退出；静默 count 完成后取消，后续列表失败且不暴露部分计数。
- 浏览器能力控制器传递同一请求 context，只使用中间件 tenant/user，不采用查询字符串身份。
- 后端相关包测试、静态检查和构建通过。

```powershell
go test ./api ./internal/services ./internal/repo -run '^TestAgent(Tool|ReadTools|Capabilities)' -count=10 -timeout 90s
```

没有生产延迟改善比例或吞吐结论。主要收益是限制无效数据库等待，不表示 SQL 查询本身变快。

## 发布与剩余边界

- 仅后端镜像，无数据迁移、配置、依赖或协议字段变更；可回滚到前版本。前端/独立 Agent 未改，未部署生产、调用真实模型或重跑浏览器。
- 用户取消后，审计允许继续等待最多 10 秒；因此不能承诺整个 HTTP 处理立即退出。
- 写操作预览/确认的数据库及缓存副作用仍沿用原逻辑，不在本批中止或自动重试，防止把未知执行结果当作失败重做。
- Redis v6 进行中的读取仍不能被 context 中断，真实 MySQL 查询中断和生产容量未验证；单次 JSON 编解码也不是可抢占工作。
- 审计结果目前先序列化再截断，单条存储有 32 KiB 摘要限制但序列化临时开销仍需后续评估。工具审计保留期限、可靠持久化策略及其他全系统待办继续保留。
