# 故障中心选择器避免重复全量告警统计

日期：2026-10-10。后端基线 `503ec9c`，前端基线 `eac0d93`，独立 Agent 不变。

## 代码证据与范围

`faultCenterService.List` 为每个中心读取全部缓存事件、解码并累计三类计数。此前前端首页、告警工作台、规则创建/编辑、规则导入/批量修改和静默表单都调用此方法，但只消费中心 `id/name`。首页随后还会读取选定中心的 Dashboard，告警工作台另有自己的事件查询，选项读取形成额外完整扫描。

本批增加同一受保护列表接口的显式 `view=options`：

- SQL 只选择当前租户的 `id/name`，名称/ID/描述搜索条件保留；不读取路由配置，不访问 Redis。
- 单独返回 `FaultCenterOption`，不返回假零值计数或空通知配置；空选择为 `[]`。
- Controller 仍以中间件 TenantID 覆盖请求中的租户。沿用原接口鉴权/权限，不添加旁路接口。
- 新读取透传请求 context 并设置 30 秒上限，SQL 等待可取消；数据库失败不能伪装为空成功。
- 未指定 view 的原调用保持完整列表、实时计数及缓存失败语义；未知 view 也保持旧接口行为，不自动降级统计错误。
- 修正请求结构中原有 `query` 的 `from` 标签拼写为 `form`，使实际查询参数进入搜索条件。

前端新增明确命名的 `FaultCenterOptions` 包装调用，仅替换上述身份选择用途。故障中心管理页继续使用 `FaultCenterList`；首页实际指标继续来自 Dashboard，告警实际状态仍来自事件接口。没有界面布局、写操作、静默范围、权限或状态语义变更。

## 测量与边界

`TestCenterOptionsSkipEventsAndPreserveFullCounts` 使用真实缓存客户端与 miniredis：两个中心的原完整列表有两次 HGETALL，options 没有 Redis 命令；缓存不可用时，完整统计仍失败，选项查询可独立完成。

`BenchmarkCenterSelector`（Windows / Go 1.24.11 / Ryzen 7 7700，三轮各一秒）使用同样缓存链路、两个中心共 1k/10k 事件，**SQL 为 fixture**。原选择器误调用的全量统计部分：

|事件数|原统计路径耗时|原临时分配|改为选项后的事件读取数|
|---|---:|---:|---:|
|1,000|5.97–6.93 ms|约 5.04–5.06 MB|0|
|10,000|65.63–67.77 ms|约 49.27–49.28 MB|0|

选项路径在该 SQL fixture 下约 225–237 ns、392 B；这个数字只代表薄服务封装，**不能当作真实 SQL/HTTP 响应时间**。改善结论是去掉无用事件扫描，不是承诺页面在微秒内打开。分配包含同进程模拟 Redis，不等于服务 RSS。真实数据库及生产规模仍需验证。

## 验证

后端专项连续十次和相关包回归通过，相关 go vet、全项目构建通过。覆盖租户覆盖/隔离、名称/ID/描述搜索、空结果、SQL 取消和失败、只返回 id/name、不解码损坏的无关路由配置、完整计数仍读取事件及传播 Redis 错误。

前端 31 项单元测试、类型检查和生产构建通过。9 项浏览器专项连续三轮（27 项）通过；最终构建全站回归 316 项通过，2 项按需 Copilot 容量基准本批未启用。模拟 API 不等于前后端生产联调。初次专项发现测试误以为规则列表挂载就加载选项（实际在打开导入/批量修改时加载），另有 Ant Select 内部 input 被显示文字覆盖造成的定位问题；按真实操作打开导入并点击选择框后重跑通过，没有为迎合测试改变页面行为。

## 发布与回滚

前后端分别合入 `eddie`。建议先部署后端，再部署前端；无配置/数据库迁移，独立 Agent 不用更新。

- 新后端 + 旧前端：仍返回原完整列表，功能兼容，但不能获得此次选择器收益。
- 新前端 + 旧后端：旧后端忽略 view，仍返回完整列表，前端仅用 id/name，功能兼容但仍有统计开销。不做额外失败重试请求。
- 任一侧可独立回滚；本批未部署生产、调用真实模型或通知服务。

## 继续处理

真正需要计数的故障中心管理页仍有全量读取成本；本批没有采用延迟计数缓存或新的不一致计数索引。普通事件列表、静默预览的完整源数据读取，Redis 底层取消与真实容量验证仍属于整体优化待办。
