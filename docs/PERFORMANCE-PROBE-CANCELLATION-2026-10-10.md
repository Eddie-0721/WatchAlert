# 拨测取消与配置边界

日期：2026-10-10；后端基线 `ed85cd2`，分支 `codex/probe-cancellation`。仅后端变更，无新增依赖。

## 实际问题与修改

之前 `ProbeService.runProbing` 虽然监听停止 context，但执行协议探测时未传递它；远程写入使用根 context。停止只能阻止后续定时循环，无法打断当前网络等待；一个配置中的后续目标仍会继续探测、写入整批指标。即时拨测也丢弃了 HTTP 请求 context。

- HTTP 使用 `NewRequestWithContext`；TCP 使用 `DialContext`；SSL 的新连接请求支持调用者 context，不复用旧证书连接。
- ICMP 在可取消的 DNS 解析后安装解析结果，避免 go-ping 在 `Run` 内重新做不受控 DNS。保持 IPv4 优先和 IPv6 zone，DNS 使用配置的 timeout；实际 ping 仍使用其原 timeout，两阶段并非共用一个总预算。
- ICMP 取消调用依赖现有并发安全的 `Stop`，仍同步等待 `Run` 返回后才结束，不把阻塞调用丢到遗留 goroutine。取消不会返回部分统计作为失败指标。实际内核/平台退出延迟仍需集成验证。
- 四种协议保留旧调用入口，生产定时/即时入口改走 context 版本。目标自身超时仍产生原失败指标；调用者取消返回无指标，服务层返回取消错误，不输出成功空数据。
- 定时执行在每个目标前后、申请写入客户端之后检查取消；一旦取消丢弃该轮部分结果，remote write 使用规则 context。保留客户端借用/释放机制；数据源类型不符时不再强制转换 panic。
- 原有规则校验函数没有接入启动；现在创建、修改、启用、启动均验证配置。周期、超时、ICMP 间隔必须为正且转换成 `time.Duration` 不溢出，ICMP count 必须为正；拒绝空目标段、未知协议/HTTP 方法。即时拨测不要求未使用的评估周期。
- 启用先按租户读取并验证已保存规则；无效旧配置仍允许停用。该控制器原先未将可信租户填入请求，现在覆盖正文 tenantId，服务层拒绝空租户/规则 ID。未修改权限目录或添加角色授权。
- 取消不再写“即时拨测完成”日志或记录成远程写入失败。

## 验证范围

新增 13 个顶层测试，包含多组子场景：

1. 真实本地 HTTP/TLS 慢服务：原目标 timeout 为 30 秒，取消后在测试 1 秒等待窗内退出，并被服务端观察到；取消不输出失败指标。
2. 三目标定时执行：第一目标成功、第二目标阻塞时停止；第三目标零访问，无 Redis/写入客户端访问，执行函数真实退出，部分指标不提交。
3. 真实本地 Prometheus remote-write 接收端：写入已开始后取消，接收端看到请求断开、调用返回。**不能推导已收到的数据被撤销。**
4. TCP 预取消及正常连接释放、SSL 正常证书指标；真实 HTTP 1 秒目标超时仍输出失败指标。未模拟操作系统 TCP SYN 阻塞取消。
5. ICMP 的同步 Run/Stop 替身验证取消会停止且必须等待 Run 完成；Go Resolver 使用隔离 Dial fixture 验证 DNS 取消；真实字面 IPv4/IPv6/zone 解析。未发送真实 ICMP 报文，未验证 Linux raw socket 权限或不同平台内核行为。
6. 非法周期、溢出、超时、目标/类型/ICMP 参数在注册任务前拒绝；有效最大 duration、即时无周期、父任务预取消均覆盖。
7. 无效创建/修改在持久化前拒绝；旧无效规则不能启用但仍能进入停用；API 透传 context、覆盖不可信正文租户。

专项最终连续 10 次、后端相关包非缓存回归、`go vet` 和 `go build ./...` 均通过。不把这些本地证据换算为生产 p95 或吞吐收益。上批 HTTP 私有池释放测试仍保留。

## 发布、兼容与仍需处理的内容

仅后端镜像，无 SQL/Redis 格式、前端 JSON 字段、依赖版本或配置文件格式变化。前端和 Agent 不需要因本批单独更新。未部署生产、未调用生产数据源/通知/模型。

**发布前检查已有拨测规则的 timeout、evalInterval 及 ICMP 参数。** 之前保存的零值、负值或溢出值本批拒绝启动/启用，避免崩溃或无期限运行；不擅自为旧数据填默认值。启动日志报告拒绝，数据库 enabled 不会自动重写；需修正配置再启用，或先停用。已有合法正值不施加新的人为最大秒数。

停止仍是请求取消，不是等待所有远端副作用回滚；Stop 与新 Add 之间可能短暂存在正在退出的旧任务。规则登记/更新合并、全局拨测并发预算及批量启动额外 goroutine 尚未完成，应下一批做慢目标生命周期测试，不能称拨测整体调度已验收。

远程写入、旧存储操作和网络对端可能已经接受请求，取消不能保证零外部副作用。真实 ICMP、Linux 容器、Redis/MySQL、生产负载仍是待验收边界。

第三十九批后续状态：同规则旧新任务合并、共享容量和启动额外 goroutine 已处理并本地回归，见 [拨测调度记录](PERFORMANCE-PROBE-DISPATCH-2026-10-10.md)；真实环境验证和浏览器发起取消仍不能由本文替代。
