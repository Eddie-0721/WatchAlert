# 静默预览的有界样本构建

日期：2026-10-10。后端基线 `14b2e42`，仅修改后端。

## 发现与修复

`internal/services/silence_preview.go` 原实现为所有匹配告警构建 `SilencePreviewSample`（包含七项 Scope）、排序完整的大结构体切片，最后只返回前五条。切片截取还会使返回结果暂时引用整个样本数组。

该路径同时用于页面预览、创建/修改静默前的复核，以及 Agent 创建/修改静默建议时的影响分析。普通告警列表不受此改动影响。

现改为扫描时保留所有匹配指纹，以及固定五个最小指纹的事件指针；扫描结束只为这五条构建 Scope。完整指纹集合仍排序并参与原 JSON/SHA-256 校验。保留原始事件对象，不修改标签或状态，不增加跨请求缓存。

保持以下行为：

- 租户、故障中心、恢复状态和 Label 匹配过滤不变。
- Total 是完整匹配数，Samples 仍按指纹升序最多五条，空样本仍为 `[]`。
- Truncated、PreviewHash、PreviewAt 字段和校验协议不变；创建/修改的权限和确认流程不变。
- 前五条之外的匹配告警增减仍改变校验摘要，旧确认不能继续提交。
- SQL/Redis 失败仍阻止预览，原配置变更、预览过期等检查继续保留。

未增加新索引、配置或接口，没有数据迁移。事件写者要求 hash field 与 fingerprint 一致、同中心唯一；本批不为损坏数据的重复指纹定义新的样本选择协议（原实现对此也无稳定顺序保证）。

## 前后测量

`BenchmarkSilencePreview` 修改前后各运行三轮，每轮一秒，Windows / Go 1.24.11 / Ryzen 7 7700。真实服务方法、内存 SQLite 中心校验、预解码缓存 fixture；所有输入事件都匹配，含二十个 Label。测量含条件匹配、采样、摘要编码及 SQL 调用，**不含 Redis 网络/JSON 解码**，不是生产延迟、服务 RSS 或容量承诺。

|匹配告警|原耗时|现耗时|原分配/请求|现分配/请求|
|---|---:|---:|---:|---:|
|5|11.31–11.58 µs|10.76–10.94 µs|约 6.8 KB|约 5.1 KB|
|1,000|0.708–0.724 ms|0.145–0.155 ms|约 366 KB|约 55 KB|
|10,000|11.60–11.98 ms|1.80–2.08 ms|约 6.38–6.40 MB|约 0.827–0.840 MB|

独立结构测试也确认：1,000 个匹配事件，旧参考实现构建 Scope 1,000 次，现实现仅 5 次，响应内容及摘要一致。不是仅依赖计时判断优化有效。

仍须完整读取/检查事件并保留全部指纹：总成本不是常数，指纹排序仍为 O(n log n)，Redis 和解码开销没有消除。不会用随机采样的五条代替静默真实影响范围。

## 验证与发布

- 100 组筛选对比独立的原实现，含其他租户/中心、空事件、不同状态和非匹配标签。
- 0/1/4/5/6/1,000 条边界验证，完整响应（除动态时间戳）与旧参考一致。
- 五条外的匹配变更：展示样本不变，Total 与摘要必须改变。
- 原有静默新鲜度、租户隔离、原配置变更、失败阻断回归保留；全部静默预览专项连续十次通过。
- 后端相关包测试、`go vet ./internal/services`、`go build ./...` 通过。未运行可能连接外部系统的示例测试；无 Windows CGO race 条件。
- 没有前端/独立 Agent 文件修改，本批不重复浏览器验收。未部署生产、调用真实模型或发送通知。

合入后端 `eddie` 后只需重建后端镜像；前端/独立 Agent 不需要配套升级，可独立回滚本提交。

## 剩余项

故障中心列表仍为统计计数读取完整事件，普通当前告警查询及静默预览仍有全量读取成本。Redis v6 在途取消限制、真实 SQL/Redis 容量与生产运行数据、规则索引实际启用条件等仍待处理/验证。本批不宣称整体性能目标完成。
