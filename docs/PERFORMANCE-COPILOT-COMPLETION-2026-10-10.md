# Copilot 完成边界与数据库等待

日期：2026-10-10。后端基线 `c1e3666`。本批仅后端变更，前端和独立 Agent 不变。

## 已复现问题

`StreamMessage` 直接转发内部 Agent 的 `done`，随后才写 assistant 消息；写入失败时浏览器已经收到完成事件。内部流在 done 后又返回错误，也会产生先完成后失败的矛盾。流式/普通消息接口都会忽略会话标题和更新时间的保存错误。

消息写入未使用 HTTP 请求 context，模型调用的超时不覆盖随后数据库连接等待。已有历史读取虽传递 context，但未设置自身等待上限。

本地真实 HTTP 测试 + SQLite 注入错误在修改前复现：done 回调查不到回复、assistant 写入失败仍有 done、会话更新失败仍返回成功、上游尾部错误前已转发 done。

## 修复

- status/delta 仍实时透传；内部 done 不直接发送。完整上游读取成功、回复及会话元数据事务提交成功后，发送一次现有结构的 done。
- 普通消息接口复用同一回复保存逻辑，不忽略元数据写入错误。
- 用户消息保存、回复保存和运行前历史读取各有 10 秒数据库阶段预算，并继承调用方更早的超时或取消。
- 事务只覆盖回复和会话更新，不跨模型调用；不占用数据库连接等待模型。
- 用户消息仍先行保存；失败后不自动重试模型或任何工具写操作，不增加跨请求状态缓存或并发架构。

这是异常情况下减少无效数据库等待、保证完成状态真实性的修复，没有宣称正常模型推理变快。消息保存本来就必须完成；额外事务使会话元数据与回复作为同一提交边界。

## 验证

专项连续 10 次通过：

- 流式/普通成功、用户消息/assistant/会话写入失败；元数据失败回滚 assistant，不删除先前用户消息。
- done 回调直接读取数据库，确认回复内容、证据、会话标题和更新时间已经保存。
- 内部 done 后的 error 不向浏览器发送 done，也不保存 assistant。
- 数据库仅一个连接时，模拟 Agent 请求中仍可查询数据库，验证模型等待期间没有占用事务连接。
- 耗尽连接池时，历史读取和两类写入均遵守调用方 30ms 截止时间，取消后无新增消息。此测试只证明本地连接池取消，不是生产 SQL 延迟基准。
- 服务级真实 HTTP：收到 delta 后取消请求，上游连接得到取消，未保存部分 assistant、未发送 done。
- 后端相关包测试、静态检查及构建通过。

复现入口：

```powershell
go test ./internal/services -run '^TestAgent(Completion|DatabasePool)' -count=10 -timeout 90s
```

## 发布及未验证边界

- 仅需后端镜像，不新增接口字段、配置、依赖或迁移；可回滚到本批前版本，但旧完成顺序问题会恢复。
- MySQL 的 `w8t_agent_messages`、`w8t_agent_sessions` 必须为支持事务的引擎（例如 InnoDB），实际生产引擎未验证，不能仅凭 SQLite 断言生产回滚有效。发布前可由管理员查询 information_schema.TABLES 核实，不自动修改表引擎。
- 未部署生产、调用真实模型或重跑浏览器；检查了现有前端 done 字段契约，协议形状不变。
- 请求在提交成功后、完成事件到达前断开，历史可能已保存但客户端不知道；不能承诺端到端 exactly-once。未知结果应先重新加载会话，不自动重发分析/操作。
- 能力/配置读取仍沿用现有仓库接口，此批未把所有配置与权限查询改造为 context 接口；不宣称整个请求每一阶段均可取消。
- 未模拟真实 MySQL 网络中断导致的提交结果不确定，也未解决跨请求重复发送、跨副本操作投递和生产容量；这些仍是后续边界。
