# 精确告警查询避免全中心读取

日期：2026-10-10。后端基线 `df5b89d`，本批仅修改后端。

## 代码证据与改动

`eventService.ListCurrentEventContext` 原本先为每个中心调用 HGETALL/解码，再用 `request.Fingerprint` 过滤。Agent 的 `alerts.get` 复用此服务，即使已知指纹也会扫描全中心；`alerts.related` 获取源告警时同样受影响。

新增 `GetEventsByFingerprintContext`：非空指纹使用 HGET 只读取相应字段。普通无指纹查询仍保留 HGETALL，不截断列表、不改变摘要。两种读取复用同一个 JSON 解码函数，保留已有非法 JSON 行记录日志并跳过的行为。缺失字段是空选择，连接错误、Redis 类型错误仍是失败。

后续仍走原过滤链：租户、指纹、规则、Agent 数据源/环境授权、严重度、时间、搜索、静默、状态、摘要和分页。指定中心仍须属于该租户中心列表；未指定中心仍逐中心查询，不能命中第一条就提前成功。Agent 仍拒绝跨中心同指纹的歧义结果，后续中心存储失败仍传播。

这是复用已有存储结构：事件写入/CAS、原 `GetEventFromCache` 已将 fingerprint 作为 Redis hash field，不新建索引或更改键格式。不支持把记录手工存到与自身 fingerprint 不一致的字段；本批不修复或迁移这类损坏数据。

## 固定规模基准

`BenchmarkExactCurrentEventRedis` 在修改前后分别运行 3 次，每次 1 秒。两中心共 1k/10k 事件、每中心 100 条静默，查询同一条存在的告警，包含真实 go-redis 客户端/生产解码与静默计算，连接同进程 miniredis；故障中心 SQL 使用 fixture。Windows / Go 1.24.11 / Ryzen 7 7700。

|事件总数/范围|修改前耗时|修改后耗时|修改前分配|修改后分配|
|---|---:|---:|---:|---:|
|1k，指定中心|3.17–3.19 ms|0.200–0.203 ms|约 2.68 MB|约 133–135 KB|
|1k，两个中心|6.16–6.23 ms|0.234–0.237 ms|约 5.20 MB|约 133–134 KB|
|10k，指定中心|31.06–31.38 ms|0.198–0.202 ms|约 24.8 MB|约 129–130 KB|
|10k，两个中心|62.69–64.34 ms|0.231–0.236 ms|约 49.4 MB|约 129–131 KB|

实际 Redis 命令测试确认事件 hash 只发 HGET，普通无指纹查询仍发 HGETALL；变化主要是传输/解码行数，不是声称 Redis 往返次数归零。100 条静默仍需要读取并计算，因此精确查询也不是完全无分配。

上述数据不是生产响应时间或 AI 总耗时；分配计数包含同进程模拟 Redis，不等于服务 RSS。中心数量增加时，无中心查询仍随中心数增长；本批没有全局指纹索引，也没有改变查询歧义语义。

## 验证

- 精确/全量读取解码一致：命中、缺失、非法 JSON、空指纹拒绝、Redis 类型错误。
- 已取消请求不访问 Redis，读取后取消不返回成功，包括不存在指纹；Redis v6 在途网络读取限制仍存在。
- 128 组中心/指纹/队列/分页组合，另加摘要、恢复排除、规则、服务、环境与 Agent 作用域条件，对比独立的原全量筛选参考实现。
- 验证负载中租户/中心/指纹与请求不匹配时不返回，静默读取失败不能误报为未静默。
- 真实缓存适配器测试 Agent 单条获取、跨中心同指纹歧义、指定中心消歧和晚到中心错误；原身份/权限回归保留。
- 新增精确读取用例连续 10 次通过；完整后端相关包回归、相关 go vet 与 `go build ./...` 通过。
- 无前端和独立 Agent 改动，本批未重跑浏览器，未部署生产、调用真实模型或发送通知。Windows 无 CGO race 验证条件。

## 发布与剩余项

合入后端 `eddie`，仅重建后端镜像。无接口、配置、数据库表或 Redis 格式变更，可独立回滚后端。

只有提供明确指纹的查询受益；普通告警列表和关联分析的候选列表仍是全量读取。未增加高风险长期缓存或不一致的局部摘要。Redis 真实取消、其他已识别的前端请求和长会话成本、生产容量验证仍需继续，不宣布整体性能优化完成。
