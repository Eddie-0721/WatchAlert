# 故障中心实时统计的内存与取消优化

日期：2026-10-10。后端基线 `27d79f7`，前端/独立 Agent 不变。

## 问题与实现

上批已将身份选择器与真实统计分离；本批针对故障中心管理页仍需要的完整统计。原路径逐中心 HGETALL、构建所有事件的 `map[string]*AlertCurEvent`，再遍历累计三个状态数量。hash field 和全部解码对象只为计数暂存，均不属于返回内容。

新增 `AlertCache.CountEventStates`：

- 使用 HVALS 一次读取当前中心的全部值，不传输无用的 hash field，不创建全量解码事件 map。
- 完整解码每条 `AlertCurEvent`，只累计 `pre_alert/alerting/pending_recovery`，与原有计数一致；其他状态不累计。
- 每轮清零并复用外层事件结构，不保留上一条的状态、Labels 或部分失败解码字段。保留完整类型校验和坏行记录日志后跳过的原行为，不把只有合法 status 的损坏事件算作有效告警。
- 不修改事件、使用过期计数缓存、建立新索引或分页截断。单中心仍一次完整 hash 读取，不以多次 HSCAN 拼接结果改变读取时序；跨中心仍逐一读取，不宣称跨中心事务快照。

完整列表的 HTTP context 透传到 SQL 和统计，服务上限 30 秒。SQL 连接池等待可取消；Redis 读取前/后、逐条解码及最终返回前检查取消。错误/取消返回失败，不暴露部分计数或把失败改为零。内部启动枚举仍通过保留的 `List("", "")` 兼容入口运行，原租户/搜索/配置字段行为不变。

**当前 Redis v6 仍不能通过请求 context 打断已经进行的网络读写。** 本批没有依赖迁移，也没有用额外后台 goroutine 假装取消；限制与此前记录一致。

## 对照测量

`BenchmarkCenterStatistics` 同时保留旧读取/全量对象计数参考实现与新实现。Windows / Go 1.24.11 / Ryzen 7 7700；两个中心总共 1k/10k 事件、相同 Labels/状态分布，真实缓存适配器与同进程 miniredis，SQL fixture。每个场景三轮、每轮两秒。正式对照测量期间未同时运行其他编译/测试。

|事件总数|旧路径耗时|新路径耗时|旧分配/请求|新分配/请求|
|---|---:|---:|---:|---:|
|1,000|5.94–6.19 ms|5.64–5.78 ms|5.04–5.06 MB|4.21–4.23 MB|
|10,000|59.70–60.80 ms|55.67–56.31 ms|49.27–49.32 MB|41.42–41.48 MB|

10k 场景总分配约减少 16%，分配次数约 360k→320k。主要收益是减少无用对象及 hash 字段传输，耗时改善较小，不声称数量级提速。初次单独基准与编译重叠、耗时波动较大，因此采用上述不重叠的并排结果，不引用初测离群值作为收益。

分配包含同进程模拟 Redis，不等于后端 RSS 或生产峰值内存。HVALS 仍把全部原始 JSON 值读入内存，完整解码成本也仍存在；这不是流式网络解析、O(1) 总内存或生产延迟/容量证明。

## 验证

- 缓存计数对比原完整 typed decode：所有状态、null/空对象、坏 JSON、其他字段类型错误、嵌套 Label、状态转义/大小写/重复键、同正文指纹的不同 hash 行、认领/恢复标志，均按旧规则计数。
- 顺序用例验证外层解码对象复用不串行污染；坏行部分赋值后下一行缺省状态不能继承。
- 确认每中心仅一条 HVALS；空 hash 为成功零计数，错误类型/缓存失败不是零成功。
- 已取消、读取后取消（含空 hash）、解码中取消、第一/最后中心完成后取消，都拒绝部分结果。
- 真实缓存服务完整响应与独立旧实现比较；晚到中心读取失败拒绝已计算的首中心结果。
- SQL 租户限定/配置保留、内部跨租户启动列表兼容、SQL 连接等待取消，HTTP 请求 context 传递。
- 新增/相关专项连续十次、后端相关包回归、相关 go vet 与全项目构建通过。Windows 无 CGO race 验证条件。
- 未修改前端/独立 Agent，本批未重跑浏览器，也未部署生产、调用真实模型或通知。

## 发布与剩余边界

仅后端合入 `eddie`，只需重建后端镜像，接口响应/配置/数据库与 Redis 数据格式不变，可以独立回滚。**如 Redis 使用精确命令白名单，部署前需允许对告警键执行 HVALS**；普通 read 命令权限已覆盖此类读取。权限不足会明确失败，不会伪造空计数。本批没有修改生产 ACL。

普通告警列表和静默预览仍需完整源数据，管理页统计也仍有全值传输/解码成本。真正减少源数据读取需要结合生产规模、更新一致性和索引迁移条件评估；Redis 底层取消、实际 SQL/Redis 容量及其他既有待办继续保留。整体性能目标尚未完成。
