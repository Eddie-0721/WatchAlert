# 数据源客户端生命周期与查询预算（2026-10-10）

基线后端 `116ea55`；开发分支 `codex/performance-client-lifecycle`。只改后端，不修改独立 Agent、前端或生产配置/数据。

## 改动

| 路径 | 处理 | 保留的边界 |
|---|---|---|
| 数据源客户端池 | 获取客户端时记录使用次数，调用结束后释放；更新/删除先让旧实例退出池，最后一个使用者退出后才 Close。覆盖全部原 GetClient 调用方 | 不是跨进程客户端同步，也没有在后台强制中断旧查询；旧查询依靠自身 context/超时完成 |
| 临时客户端 | 健康检查与日志预览对支持 Close 的实例显式释放；预览传递真实 HTTP request context | 不伪称全部第三方 SDK 都有统一关闭能力 |
| Elasticsearch | 关闭 SDK 自动健康轮询及构造时探测；查询复用共享 Transport，保留原查询 TLS 校验；显式请求超时、取消、8 MiB 响应限制；拒绝超时/提前终止/失败分片的结果 | 保留原命中样本计数语义；不将样本条数改成全索引总量。本批没有解决所有日志 limit 的业务计数问题 |
| Elasticsearch 解析 | 直接解码每个 hit 的 `_source`，不再把完整 hits 序列化一遍再解码 | SDK 原始响应解析仍存在，只移除二次整段转换 |
| Elasticsearch 字段规则 | 评估端补传已有 Scope 对应的起止时间；缺失/无效范围明确失败，不再 nil 断言 panic 或无范围查询 | RawJson 查询的过滤语义不改动 |
| ClickHouse | 单数据源连接最多 8、空闲 2，空闲 5 分钟/最长 30 分钟；每次 QueryContext 最长 60 秒；服务端设置结果最多 10,000 行/8 MiB、超限抛错；客户端额外行数保护 | ClickHouse 服务端设置尚未在真实实例验证；不是整个应用堆内存硬上限，单个解码块的内存由驱动/服务端实现决定 |
| ClickHouse 行扫描 | 复用 Scan 目标切片与地址，保留每行独立的结果 map；读取结束检查 rows.Err | 不共享跨查询缓冲区，避免并发污染 |
| 评估重复探测 | ES/ClickHouse 加入直接执行实际查询的列表，不再每轮创建临时客户端先做健康探测 | 手动测试连接保留；SLS/Kubernetes 等尚未完成审查，仍保留原检查 |
| 启动 | 客户端初始化限制 8 并发并等待完成后再启动评估；某个失败仍尝试其他数据源，并报告存在初始化失败 | 启动仍会加载全部数据源清单；不是无限规模优化 |

池的 Close 在锁外执行，避免关闭阻塞其他客户端获取；release 可重复调用但只生效一次。构造/设置与租用是明确所有权关系，不能把同一拥有资源的实例作为“新客户端”重复交给多个 key。项目当前设置入口均创建新实例。

## 验证

- 1,200 次并发替换/获取覆盖所有旧实例最终只关闭一次；双租用用例证明替换/删除时不会提前关闭仍在使用的实例。
- 健康检查成功、失败两条路径均释放临时实例。
- 本地 ES HTTP 服务器验证构造不发网络请求、每次评估只有一个查询、查询错误/超时/分片失败/提前终止/超大响应均不被当作成功；取消能终止在途查询。
- ES 字段规则测试检查实际发送的查询含配置的 5 分钟范围；正常 `_source` 文本/数值转换保留。
- 隔离 SQLite 测试 database/sql 查询取消、两行扫描值互不污染、10,001 行拒绝和关闭后不可查询；另检查 ClickHouse 构造后的池上限为 8。该测试不是 ClickHouse 协议/服务端预算的实测。
- 启动用例验证 64 个启用客户端全部处理、停用项不处理、一个失败不丢弃其他项、函数返回时无在途初始化，最大并发不超过 8。
- 核心 cache/provider/评估测试连续 10 次通过；随后新增字段范围/启动测试并运行完整相关后端测试通过：

```sh
go test ./cmd ./alert/... ./internal/... ./api/... ./pkg/client ./pkg/tools ./pkg/provider ./pkg/medium/... ./pkg/oidc -count=1 -timeout 120s
```

当前本机没有可用 Go race detector，重复用例不等同数据竞争检测。未调用真实 ES/ClickHouse、未访问生产、未运行带固定内网地址的历史示例，未宣称线上吞吐/p95改善。

后端二进制构建和差异格式检查通过。

## 发布与下一步

无数据库或 Redis key 迁移，无前端响应变更；仅更新后端镜像。超出查询预算会报查询失败并保留告警，不能把它解释为监控恢复。回滚前一后端镜像即可。

仍未完成：通知消费者的每条告警静默读取和每秒无变化写入、慢通知调度隔离、恢复全中心 Redis 扫描、SLS/旧 AI/拨测取消、前端长会话/大型列表、部署代理及生产基线。生命周期修复只是全系统性能目标的一部分。
