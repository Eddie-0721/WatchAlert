# 告警查询取消与缓存解码优化

日期：2026-10-10。基线：后端 `ac1c008`、前端 `66beee2`。独立 Agent 本批无代码变更。

## 已完成

- 前端告警工作台当前/历史列表透传 AbortSignal；搜索、筛选、换页、切换队列和卸载触发的 effect 清理会取消旧读取。重新发起同类读取先取消前一个请求。保留请求序号检查，避免迟到结果覆盖新视图。
- 主动取消不走 API 错误提示；真实错误保留原有反馈。没有更改认领、静默等写操作，也不把取消写操作当作回滚。
- 当前告警 HTTP 入口和 Agent `alerts.search/get/related` 传递请求 context；列表设置 30 秒协作式预算。故障中心查询使用 GORM WithContext，仅取 id/name，保留租户约束；空租户不会扩展为全租户。
- 告警/静默缓存在读取前后、解码循环中检查取消，列表在事件扫描和返回前检查取消，不返回部分列表冒充完整成功。
- 缓存告警 JSON 直接从字符串解码，省去 string→[]byte 复制；结果 map 按读取条数预分配。既有非请求调用仍可使用兼容入口。

## 必须明确的边界

项目仍使用 `github.com/go-redis/redis v6.15.9+incompatible`。检查实际依赖源码发现，WithContext 仅保存 context，网络命令仍使用客户端固定读写超时，连接池等待/重试也不受请求 context 即时中断。本批不虚构“Redis 网络取消已经完成”：

- 已取消请求不会再发起后续读取/继续解码扫描，但已经开始的 Redis 命令仍须等网络超时或命令完成。
- 30 秒是协作式预算，不是能够强行打断所有底层操作的绝对响应时限。单次 JSON 解码、正则编译/匹配及最终排序也不是可抢占的。
- 未通过关闭共享连接池、每请求新建连接或遗留后台 goroutine 伪装取消。
- Agent 的权限读取、审计写入以及非告警工具没有在本批改为全链路取消；不能据此声明所有 Agent 工具都已完成取消治理。
- 全量 HGETALL 的线性读取/解码成本依然存在。未改为可能导致摘要/筛选不完整的提前截断。

Redis 客户端迁移应单独审批、独立批次实施，覆盖 CAS/Lua、事务、索引回填、静默和通知链路，当前不升级依赖。

## 本地测量

相同 `BenchmarkCurrentEventListRedis`，1k/10k 告警、两个中心、每中心 100 条静默，默认页 30 条，3 次、每次 1 秒。Windows/Go 1.24.11，真实 go-redis 客户端/生产缓存解码适配器连接 miniredis，SQL 中心为 fixture。

|规模|修改前每次分配|修改后每次分配|修改前耗时|修改后耗时|
|---|---:|---:|---:|---:|
|1,000|8.56–8.57 MB|5.36–5.41 MB|8.83–9.12 ms|8.04–8.18 ms|
|10,000|80.87–81.01 MB|49.59–49.66 MB|88.89–101.69 ms|87.24–90.32 ms|

10k 每次分配下降约 39%，分配次数约 382,750→362,690。计数包含同进程 miniredis，不等于后端 RSS、峰值内存或生产吞吐。耗时存在系统调度和其他本地工作干扰，不据此宣称稳定的生产延迟改善；本批主要收益是减少分配及废弃请求的后续工作。

## 验证

- 新增缓存取消前/读取后/解码中止测试，确保不返回部分数据；SQL 租户/投影及连接池等待取消测试；列表取消不访问依赖/不继续中心扫描测试；三种 Agent 告警读取 context 透传测试。连续 10 次通过。
- 后端相关包完整回归、相关目录 go vet 和 `go build ./...` 通过。未运行包含固定外部配置的 provider 示例集成测试；Windows 无 CGO race 环境。
- 前端 25 项单元测试、TypeScript 检查与 Vite 生产构建通过。已有大资源包提示仍在，不是本批解决项。
- 43 项浏览器检查通过：真实 Chrome + 构建产物 + 模拟 API 验证桌面 1440px/手机 390px 的 XHR abort 事件、迟到响应隔离、刷新、无误报取消错误；同时回归工作台、认领失败、静默、Copilot、分页与懒加载。生产服务、真实数据库/Redis 和 Ingress 端到端取消尚未验收。

## 发布与回滚

前后端分别合入各自 `eddie`，Agent 不需要重新构建。接口字段、数据库表、配置和数据格式无变化，可独立发布或回滚；建议配套更新，以同时获得浏览器取消与后端协作式中止。仅更新前端不能停止旧后端内的全部无用扫描。

本批未部署生产。后续观察请求量、取消率、Redis 读取时长与内存分配；剩余工作为静默匹配复杂度、真实 Redis 取消能力、生产 SQL 索引/容量验收等，不代表整体优化完成。
